# Android 启动白屏根治需求

## 范围

本变更修复正式微信小程序在 Android 真机冷启动和重新打开时的白屏问题。根治方向是把首页首帧与完整业务依赖图解耦，并按业务能力把页面和组合根放入独立分包；不修改后端接口、用户数据模型或业务规则。

## 验收要求

### R1 — 首帧不依赖完整业务图

- 主包只注册 Bootstrap 首页；其同步依赖闭包不得包含启动、计划、训练、进度、账户或动作详情功能组合根。
- Bootstrap 必须先渲染可见的最小启动界面，再显式加载 startup 分包；分包加载失败时必须保留可重试错误态，不能白屏。
- 每个最终注册页面必须在 Taro 根模板之前包含不依赖 React/JavaScript 的原生首屏。框架首次提交前失败时必须显示固定构建诊断码；框架完成提交后原生层必须自动隐藏，不能遮挡业务页面。
- 异步块加载、注册信封、页面模块导出和渲染失败必须映射到稳定且不泄漏原始异常的诊断码，便于只凭 Android 现场截图判断失败边界。
- Android/iOS 目标声明必须同时配套可审计、包体受控的标准库兼容策略；构建须将应用/业务源码的标准库调用按使用点改写为 pure runtime helper，不能只依赖 Babel 语法转换或桌面模拟器自带的新式 API，也不得修改原生 prototype。
- 业务页面实现与功能组合根必须编译为所属分包下的物理异步 JavaScript 块；仅把 `import()` 转换成同一页面入口内的 `Promise + require` 不算隔离。
- 微信端异步块必须通过原生 `require.async` 加载，同时保留 Webpack 官方 registration payload 与 `installedChunks` 状态机；registration 必须由 `require.async` 的 CommonJS 返回值显式交给主运行时，不得依赖分包 `WASubContext` 与主运行时共享 `wx.webpackJsonp` 全局副作用，也不得引入 DOM、网络脚本加载、`eval` 或 `new Function`。
- 旧的全量 `getWeappApplication` 组合根不得再被任何页面引用。

### R2 — 功能组合根隔离

- 启动、计划、训练、进度、账户和动作详情分别使用聚焦的 Facade 与可重试惰性组合根；业务首页属于 startup 分包。
- 每个页面只能引用所属功能组合根；一个功能组合根构造失败不得污染其他功能根的后续初始化。
- 共享基础设施通过最小核心工厂创建，核心工厂不得反向静态导入任一功能组合根。

### R3 — 页面分包与路由完整

- 计划、训练、进度、账户和动作详情页面必须注册在对应独立分包中，所有现有 `PageDestination` 路由仍能精确导航到唯一页面。
- 构建产物必须证明功能源码归属相应分包，并且首页初始加载模块闭包不包含功能组合根。
- 分包页面不得在目标分包尚未装载时直接引用其静态资源；确需复用时必须先显式异步加载目标代码块，并由产物门禁验证资源存在性和 owner。

### R4 — 业务行为保持

- 登录与会话恢复、建档与计划、训练开始/记录/总结、历史与趋势、我的与隐私、动作详情的现有行为保持不变。
- 认证失效、隐私清理、训练草稿恢复和 AI 开关语义不得因拆分组合根而放宽或静默失效。
- 账号切换、退出或认证失效必须同步废止旧账号 generation；旧账号的延迟响应、队列尾任务、AI 结果和多步骤调用不得写入、清理或使用新账号的会话与本地数据。
- 本地会话缺失不能被直接视为已清理状态；新账号激活前必须确认内存与持久层的孤儿用户数据均已清除。

### R5 — Android 真机验收

- Android 真机冷启动、热启动和重新打开均能显示首页，不再白屏。
- 真机至少完成首页、计划、训练、历史、账户五条入口验证；构建、单元测试和开发者工具结果不能替代真机证据。

## 非目标

- 不修改后端、数据库、生产环境、AppID 或用户权限。
- 不提交、不推送、不上传体验版、不提审或发布。
- 不把尚未定位到的单一第三方模块推断为已确认根因；本变更以已确认的启动依赖结构缺陷为修复对象。
