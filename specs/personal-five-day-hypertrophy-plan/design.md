# 自用五日增肌计划接入设计

## 1. 方案结论

把用户计划作为系统内置、显式可选择的固定预设 `PERSONAL_5_DAY_HYPERTROPHY_V1` 接入现有候选计划生命周期：用户在“我的计划”选择预设，预览完整五日安排，再激活为新的不可变计划版本。既有通用模板和 AI 候选生成保持原逻辑，旧计划不会被自动迁移或覆盖。

固定预设不是普通模板槽位。服务端按版本化内容读取已经校验的完整处方，不经过通用目标处方改写、动作数裁剪或 AI 重排。

## 2. 数据与接口

### 2.1 预设选择

- 新增只读预设列表 `GET /api/v1/plans/presets`，返回代码、名称、目标、频率、适用场地、周摘要和版本。
- 现有 `POST /api/v1/plans/candidates` 增加可选 `presetCode`。
- 未传 `presetCode` 时走现有通用候选生成；传入受支持的代码时生成 `SYSTEM_PRESET` 候选。
- 候选仍通过现有 `candidateId` 激活，沿用归属、过期、校验和新版本机制。

### 2.2 计划快照扩展

新增字段均为可选，缺失时采用旧行为：

- 计划：`presetCode`、`presetVersion`、`executionRules`、`progressionRules`。
- 训练日：`weekday`、`focus`、`estimatedMinutesMin/Max`、`warmup`、`dayNotes`。
- 动作：`targetRirMin/Max`、`eccentricSeconds`、`perSide`、`executionGroup`、`executionOrder`、`optionalSetRule`、`notes`。

`executionGroup` 相同且 `executionOrder` 分别为 1、2 的动作构成超级组。旧快照没有该字段时继续逐动作完成全部组。

### 2.3 兼容策略

- JSON/TypeScript/Java 对新增字段都允许缺失，并规范化为空值或旧默认值。
- 已生效计划、历史版本和训练会话不做原位更新。
- 新训练会话从计划版本复制扩展处方，之后只读取会话快照，避免模板升级改变进行中的训练。
- 编辑固定预设产生普通的新版本；不回写系统预设内容，也不影响其他用户。

## 3. 规则与执行

### 3.1 固定处方校验

固定预设由版本化配置完整声明动作、正式组、次数、休息、顺序和分组。加载时执行内容完整性校验；候选阶段仍执行动作可用性、用户排除项和安全校验，但不调用通用处方个性化。

本预设允许 6 个动作项和最高 20 次，因为超级组中的两个动作分别作为动作项保存。该放宽只适用于经版本化校验的系统预设，不扩大 AI 输入边界。

### 3.2 超级组状态机

训练位置由“动作 + 轮次”决定：

1. 普通动作继续按动作内组次顺序执行。
2. 超级组 A 第 n 组完成后进入 B 第 n 组，不启动组间休息。
3. B 第 n 组完成后按分组休息时间启动计时，再进入 A 第 n+1 组。
4. 页面退出、崩溃恢复和服务端同步后，依据持久化位置与休息截止时间恢复，不重新计时。

### 3.3 可选补充组

周二最后一个固定超级组完成后，如果训练用时不超过 42 分钟且用户状态良好，显示一次三选一：划船加 1 组、弯举加 1 组、跳过。选择被追加到会话快照；不能同时选择两项，也不改变计划正式周容量。

### 3.4 热身与进阶

热身清单和递增组属于日快照，不计正式训练量。客户端沿用现有热身与休息计时能力，显示预设专属 50%×8、70%×4；周三的 75%×2～3 为带条件提示，不自动增加正式容量。

双进阶、当天降重、停滞处理和减量规则作为计划级只读说明展示；实际重量建议仍由服务端确定性进阶模块计算。

## 4. 动作内容与素材

复用 8 个语义一致的既有动作，新增需求列出的 16 个动作。动作编码按英文大写下划线命名，史密斯机归入 `MACHINE`，不新增器械枚举。

每个新增动作包含中文名称、主要肌群、动作模式、器械、难度、步骤、安全提示和 2～4 张原创静态分解图。图像必须表现准确的器械结构、身体支撑点、起止位置和运动方向；生成后纳入现有静态清单、尺寸和体积校验。任何缺图或语义不一致阻断上传或发布。

## 5. 界面设计

### 5.1 视觉规范

- 方向：训练日志式、克制、信息优先。
- 配色：沿用项目 `#0b2f28` 深绿、`#0f6b57` 森林绿、`#46c794` 薄荷绿、`#fffefb` 暖白和现有警示色。
- 字体：沿用微信端 `PingFang SC` / `Microsoft YaHei`；计时与数字沿用 `DIN Alternate`。这是对平台字体与既有品牌的一致性约束，不引入网络字体。
- 图标：使用现有图标或 CSS 几何标记，不使用 emoji。

### 5.2 页面层级

- “我的计划”增加“选择系统预设”入口。
- 预设页先显示目标、每周频率、器械条件和周总览，再展开每日动作；确认后生成候选预览，不直接覆盖当前计划。
- 计划详情以左侧星期轨道加右侧训练卡呈现；超级组用同一分组线和 A/B 标签连接。
- 训练页首屏只显示当前动作必要信息；RIR、离心、每侧和超级组下一步紧邻组记录区域，长规则折叠在训练说明中。

## 6. 失败与回滚

- 未知或停用预设代码返回明确的参数错误，不降级成另一份计划。
- 预设动作被用户排除或当前场地不支持时返回不可启用原因，不静默替换动作。
- 素材或配置校验失败时构建失败；不产生半完整候选。
- 回滚时可移除入口并停用预设；已激活版本仍靠自身快照可读、可执行。

## 7. 验证

- 后端：预设列表、候选生成、处方保真、激活回读、旧快照兼容、会话快照和超级组顺序测试。
- 客户端：预设选择/预览、计划呈现、超级组状态机、恢复、可选组三选一和旧草稿兼容测试。
- 内容：动作 JSON schema、引用完整性、16 个动作素材清单、图片尺寸/体积及逐动作语义审查。
- 全量：`mvnw verify`、`npm run typecheck`、`npm test -- --run`、`npm run build:weapp`、边界扫描、`git diff --check` 和独立代码评审。
