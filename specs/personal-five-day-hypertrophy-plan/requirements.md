# 自用五日增肌计划接入需求

## 1. 问题与目标

当前计划模板只能稳定表达动作、正式组数、次数区间和单动作休息；规则引擎还会按通用目标处方重写这些数字，并把 45 分钟训练裁剪为最多 5 个动作。因此，不能只修改 `plan-templates-v1.json`，否则用户给出的五日计划会在生成后失真。

本变更要把用户提供的周一至周五增肌增重计划作为一份可直接执行、可计时、可记录的固定五日计划接入小程序，并保持既有计划和通用生成逻辑兼容。

## 2. 范围

### 2.1 计划结构

- 目标：增肌增重，对应系统目标 `HYPERTROPHY`。
- 训练日：周一至周五；周六、周日休息。
- 周一、周二、周三、周五的热身加正式训练目标为 43～46 分钟。
- 周四是 32～38 分钟的补充训练日，不为凑时长增加动作。
- 正式动作、组数、次数区间、休息和动作顺序以用户原始计划为准。
- 热身组不计入正式训练量或进阶判断。

### 2.2 五日正式训练

| 星期 | 重点 | 正式训练 |
|---|---|---|
| 周一 | 胸、肩、三头 | 史密斯平板卧推 4×6～10；30°上斜哑铃卧推 3×8～12；器械坐姿推肩 3×8～12；前倾蝴蝶夹胸 2×12～15；哑铃侧平举与三头器械下压超级组，各 3 组 |
| 周二 | 背、肩后束、二头 | 宽握高位下拉 4×8～12；器械坐姿划船 3×8～12；单臂哑铃划船 2×10～12/侧；反飞鸟器械与哑铃弯举超级组，各 3 组；可选补充只能在划船或弯举中二选一加 1 组 |
| 周三 | 股四头、单腿稳定、核心 | 史密斯深蹲 4×6～10；坐姿腿举 3×10～12；哑铃反向箭步蹲 2×8～10/侧；坐姿腿屈伸与卷腹机超级组，各 3 组 |
| 周四 | 上胸、背、肩中后束、手臂 | 上斜哑铃飞鸟与窄握高位下拉超级组，各 3 组；哑铃侧平举与反飞鸟器械超级组，各 3 组；三头器械下压与锤式弯举超级组，各 3 组 |
| 周五 | 腘绳肌、臀大肌、臀中肌、小腿 | 哑铃罗马尼亚硬拉 4×8～10；器械臀桥 3×8～12；腿弯举器械 3×10～15；臀外展器械与站姿提踵超级组，各 3 组 |

### 2.3 热身与执行规则

- 每个训练日显示原计划中的热身清单和 4～6 分钟目标时长。
- 周一史密斯卧推、周三史密斯深蹲、周五哑铃罗马尼亚硬拉显示 50% 和 70% 递增预热组；周三允许按原规则显示可选 75% 预热组及删减辅助组提示。
- 超级组按轮执行：先完成动作 A 的本轮，再完成动作 B 的本轮，随后才启动 45～60 秒或 60 秒休息；不得把 A 的全部组做完后再做 B。
- 单侧动作必须清楚显示“每侧”，左右完成才计一组。
- 复合动作显示目标 RIR 2、约 2 秒离心；孤立动作显示 RIR 1～2，只有最后一组可接近力竭。
- 推类训练显示“可佩戴护腕”；器械切换提示控制在 30～60 秒。
- 休息计时使用计划规定值，不因为页面切换或恢复草稿而静默重置。

### 2.4 进阶与减量规则

- 计划详情显示双进阶法：达到全部组次数上限且最后一组仍有 1～2 次余力后，再增加最小重量。
- 上肢复合动作建议总重量增加 1.25～2.5 kg；下肢复合动作增加 2.5～5 kg；孤立动作先达到次数上限再加最小档位。
- 第一组低于次数下限时提示当天降重 5%～10%；仅最后一组少 1 次时保持原重量。
- 连续 3 周无进步时依次提示检查睡眠和体重、主要动作增加 20～30 秒休息、删除 1～2 个辅助组，必要时减量一周（组数约减三分之一、重量减 5%～10%）。

### 2.5 动作内容

- 动作库必须能准确区分本计划使用的器械和角度，不得用哑铃卧推图片冒充史密斯卧推，也不得用高脚杯深蹲冒充腿举或史密斯深蹲。
- 新增动作至少包含：史密斯平板卧推、30°上斜哑铃卧推、器械坐姿推肩、前倾蝴蝶夹胸、器械坐姿划船、反飞鸟器械、史密斯深蹲、坐姿腿举、哑铃反向箭步蹲、坐姿腿屈伸、卷腹机、上斜哑铃飞鸟、器械臀桥、腿弯举器械、臀外展器械、站姿提踵。
- 宽握高位下拉、窄握高位下拉、单臂哑铃划船、哑铃侧平举、三头器械下压、哑铃弯举、锤式弯举和哑铃罗马尼亚硬拉可复用已有且语义一致的动作内容。
- 计划和新增动作不得依赖弹力带。
- 新增动作说明和静态分解图在进入公开发布前仍须经过独立专业内容审核；本任务不授权正式发布。

## 3. 验收标准

1. 当用户选择增肌、每周五练、45 分钟和健身房器械条件时，系统应能生成或选择这份固定五日计划，且不得用通用 3×8～12 处方覆盖原始数字。
2. 当计划生成、保存为新版本、重新打开或恢复训练时，系统应保持星期、动作顺序、正式组数、次数区间、休息、单侧标记、超级组关系和可选组规则不变。
3. 当用户完成超级组动作 A 的一组时，训练流程应切换到动作 B 的同轮；完成 B 后才启动该超级组休息计时。
4. 当用户查看某训练日时，系统应显示该日热身清单、预计时长、训练重点和适用的执行提示。
5. 当用户查看计划规则时，系统应显示 RIR、离心节奏、双进阶、当天降重、停滞处理和减量规则。
6. 当用户查看新增动作详情时，系统应显示与动作名称、器械和阶段一致的中文说明及项目原创静态分解图；任何缺图或语义不一致应阻断体验版/公开发布门禁。
7. 当既有用户打开旧计划或旧训练草稿时，系统应按原来的普通顺序执行；新增字段缺失不得造成解析失败或数据迁移丢失。
8. 当运行内容校验、后端测试、客户端类型检查、客户端测试和微信构建时，所有检查应通过，且不得改写当前已有的计划编辑器未提交工作。

## 4. 非目标

- 不自动修改线上或共享数据库中的现有用户计划。
- 不上传体验版、不提审、不正式发布。
- 不提供医疗诊断、康复建议或绝对起始重量。
- 不把用户自用计划自动推广为所有用户的唯一默认计划；启用入口和适用条件须在设计阶段明确。
